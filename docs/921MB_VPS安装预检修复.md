# 921MB VPS 安装预检修复验收

## 根因

用户图片显示 SSH 上传成功后报错：

```
[TG115][ERROR] 内存不足 2GB，当前约 921MB
TG115_RESULT=FAILED
```

报错来自 `payload/remote_install.sh` 原第145行：`TOTAL_MEM_MB >= 1800` 为硬性条件。旁边还保留了固定空闲磁盘 `>=8000000KB` 门槛。两条检查都在 APT 安装前执行。此前只修改推荐配置和 Docker 健康探针，没有覆盖这个安装预检层，因此未解决用户实际报错。

## 修复

- 删除固定最低总内存、固定总磁盘推荐告警及固定8GB空闲磁盘安装门槛。
- 内存、磁盘探测仅作参考日志，读取失败显示未知，不再触发 `set -e/pipefail` 中止安装。
- 未替换成另一组较低硬件门槛。
- root、支持的系统/架构、目录和必填配置检查保留；实际 APT/Docker/FUSE/容器启动失败仍报错。
- 115 与 Google Drive 仍共用 CD2 WebDAV 路线。推荐预算仍为2GB/6GB和20GB/20GB。

## 分工与复核

主 Agent 负责规划、独立复现、逐提交审阅、整合、EXE打包与验收。三个子 Agent 使用 `mistral/deepseek-v4-1-flash-1017`（provider=`magpie`），分别执行安装脚本修复、17项Bash沙箱回归、跨入口审核与文档更新；三个进程均exit 0。

主 Agent 另外修正了测试中依赖主机实际内存的假设，并纠正文档中“可用内存低于软阈值时窗口立即固定为1”的不精确表述：实际为下载和上传窗口分别逐步收缩到1。

子 Agent 原始报告及运行清单已存 `.local/evidence/low-memory-921/agents/`。子 Agent 在隔离 worktree 中曾因缺少本地忽略的 Compose 工具发生测试错误；主工作树工具完整，最终全量复核均通过。

## 运行期边界

> 后续更新：真实 921MB VPS 部署后约有 340MB 可用内存，512MB 硬阈值使任务一直排队；最小配置的运行期内存阈值已改为 256MB/128MB（宽裕配置仍为 1024MB/512MB），窗口被压到 0 时会记录警告并在 /status 显示原因。下文为当时的记录。

本轮修复安装拦截，未修改运行期资源保护：可用内存低于512MB时下载和上传窗口为0；512MB至不足1024MB时窗口分别逐步收缩到1；磁盘剩余小于或等于用户设置的保留线时暂停新下载。因此，921MB机器不再被安装前预先拒绝，但真实安装、启动及持续传输表现仍取决于实际可用资源与服务状态，本机未做真实VPS验收。
