# 一键部署前填写信息清单

> 不要把真实密码写进这份 Markdown。真实秘密只在部署器弹窗中填写。

## VPS

### 推荐配置

| 使用强度 | CPU | 内存 | 硬盘 | 适用情况 |
| --- | ---: | ---: | ---: | --- |
| 最小配置（默认推荐） | 1 核 | 1GB | 20GB | 部署器默认选项：本地任务预算 2GB、磁盘最少保留 6GB |
| 宽裕配置（可选） | 建议 2 核 | 建议至少 2GB | 约 50GB | 本地任务预算 20GB、磁盘最少保留 20GB，适合经常批量转发 |
| 大量或长期批量传输 | 4 核 | 8GB | 80～100GB SSD | 给容器、并发任务和 CloudDrive2 缓存留下更多余量 |

- 推荐 Ubuntu 22.04/24.04 或 Debian 12 64 位；
- 具有 root 或可用的 sudo 权限；
- 勾选“在 VPS 中安装并管理 CloudDrive2”时必须支持 `/dev/fuse`；复用已有 CloudDrive2 时不需要；
- 推荐公网 IPv4，或者其他能够从本地稳定建立 SSH 连接的地址；
- VPS 应能稳定访问 Telegram 和 Docker 镜像仓库；
- 端口带宽建议 100Mbps 或以上，并准备足够的月流量。每个文件都要经过 VPS 下载和上传，
  服务商可能只统计出站，也可能同时统计入站与出站，应以服务商计费规则为准；
- 最小配置的 2GB 只限制 Bot 普通落盘，6GB 是整块磁盘至少留出的空闲；CloudDrive2 的内部
  缓存不计入这 2GB，因此仍要关注真实剩余空间；
- 单文件超过本地任务预算时会自动使用流式模式，不需要把预算调到文件大小；流式中断后
  会从头重试，CloudDrive2 仍可能使用自己的缓存；
- 两个 VPS 配置推荐预算和磁盘保留，并写入对应的运行期内存阈值（最小配置 256MB/128MB，宽裕配置 1024MB/512MB），不按内存做配置健康检测。两类配置只是推荐，部署脚本
  不做固定最低内存/总磁盘/空闲空间安装拦截；实际安装出错仍会报错，运行期磁盘保留和资源调度
  继续生效。

### 需要填写

- [ ] VPS IP 或域名
- [ ] SSH 端口
- [ ] SSH 用户名
- [ ] 登录方式：密码 / SSH 私钥
- [ ] VPS 密码，或者 SSH 私钥文件
- [ ] 私钥口令（如果有）
- [ ] sudo 密码（非 root 且非免密 sudo 时）
- [ ] VPS 系统为 Ubuntu / Debian 64 位
- [ ] 若由 VPS 托管 CloudDrive2：VPS 支持 `/dev/fuse`
- [ ] VPS 配置选项：最小配置（默认，20GB 硬盘）或宽裕配置（约 50GB 硬盘）
- [ ] 磁盘约 20GB（最小配置）/ 约 50GB（宽裕配置）——推荐值，不是安装门槛
- [ ] 内存 1GB（最小配置）/ 2GB 左右（宽裕配置）——推荐值，不是安装门槛

## Telegram

- [ ] Bot Token
- [ ] Telegram API ID
- [ ] Telegram API Hash
- [ ] 本人 Telegram 数字 ID

## CloudDrive2（两条路线都需要）

- [ ] CloudDrive2 会员账号；当前方案按会员环境设计，并要求目标网盘挂载和 WebDAV 功能可用
- [ ] WebDAV 用户名
- [ ] WebDAV 密码
- [ ] 在 CloudDrive2 管理页登录并挂载本次选择的网盘（115 或 Google Drive）
- [ ] 该网盘剩余空间足够
- [ ] 确认 WebDAV 根目录；若已经选中目标 Telegram 文件夹，相对路径留空
- [ ] 决定是否勾选“在 VPS 中安装并管理 CloudDrive2”（默认勾选；两条路线都适用）
- [ ] 挂载后执行“WebDAV 验收（写入测试文件）”
- [ ] 验收界面明确显示 `TG115_DESTINATION=OK`

CloudDrive2 会员账号、115 登录和 Google 授权只在 CloudDrive2 管理页由本人操作，不填写进
部署器，也不提交到 GitHub。部署器需要的是你在 CloudDrive2 中另外设置的 WebDAV 用户名和
密码。

## 网盘账号（按选择准备其一）

### 选择 115

- [ ] 一个有足够空间、可正常登录的 115 账号（115 会员不是程序代码的硬性要求）
- [ ] 已在 CloudDrive2 中挂载 115，并能浏览文件
- [ ] 部署器“目标网盘”选择 `115`
- [ ] 填写 115 在 WebDAV 根目录下的相对路径；留空表示直接写入 WebDAV 根目录
- [ ] 部署后执行 `sudo /opt/tg115/manage.sh verify`，确认 `TG115_DESTINATION=OK`
- [ ] 在 115 官方客户端确认测试文件可见后再批量使用

### 选择 Google Drive

- [ ] 一个有足够空间的 Google 账号（My Drive 或你有权限的共享盘）
- [ ] 已在 CloudDrive2 管理页完成 Google 授权并挂载 Google Drive，能浏览文件
- [ ] 部署器“目标网盘”选择 `Google Drive`
- [ ] 填写 Google Drive 在 WebDAV 根目录下的相对路径；留空表示直接写入 WebDAV 根目录
- [ ] 部署后执行 `sudo /opt/tg115/manage.sh verify`，确认 `TG115_DESTINATION=OK`
- [ ] 在 Google Drive 网页或客户端确认测试文件可见后再批量使用

Google Drive 路线不需要 OAuth token、client ID/secret、根目录 ID 或 `/dev/fuse`；Google 授权
完全在 CloudDrive2 内完成，本程序不访问 Google API。

## 推荐保持默认

- [ ] 目标网盘：`115`（`DESTINATION_TYPE=clouddrive2`）或 `Google Drive`（`gdrive`）
- [ ] 安装目录：`/opt/tg115`
- [ ] VPS 配置：`最小配置（推荐）`（只推荐 2GB 预算和 6GB 保留）
- [ ] 本地任务预算：`2GB`（宽裕配置为 `20GB`，可手工修改）
- [ ] 磁盘最少保留：`6GB`（宽裕配置为 `20GB`，可手工修改）
- [ ] 时区：`Asia/Shanghai`
- [ ] 勾选“在 VPS 上安装并管理 CloudDrive2 容器”（默认勾选，与选择哪个网盘无关）

## 明确不需要提供

- Telegram 私人账号密码；
- Telegram 二次验证密码；
- 115 密码给 Codex；
- CloudDrive2 会员账号密码或登录 Cookie；
- Google 账号密码、OAuth token、client ID/secret 或文件夹 ID；
- GitHub 账号密码。
