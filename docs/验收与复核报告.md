## 一、结论

v1.5.0 已修复此前审核中确认的代码问题：超过本地预算的单文件永久排队、上传最后阶段
取消产生远端孤儿文件、下载改名时崩溃产生本地孤儿文件、缺失文件继续占用额度，以及
CloudDrive2 容器误识别。

历史基线为 75 项自动化测试、Python 编译、Ruff、Bandit、pip-audit、Windows EXE 打包自检，
以及当时的 GitHub Actions Linux ShellCheck、Compose 校验和 Bot 镜像构建。

本地开发版在 v1.5.0 基础上新增 Google Drive 目标，但**两条路线都经过 CloudDrive2**：

```text
Telegram → VPS → CloudDrive2 → 115
                            → Google Drive
```

Google Drive 由用户在 CloudDrive2 管理页登录挂载，本程序不处理 OAuth token、client ID/secret
或文件夹 ID，也不直接请求 Google API。这部分只完成本地代码、部署脚本、Compose 和文档验证，
没有发布新版本，也没有在真实 VPS 或真实网盘上跑通端到端传输。

这些检查证明程序逻辑和交付包在可自动验证范围内成立，但不能替代以下真实验收：

1. CloudDrive2 是闭源特权容器，无法进行源代码级安全证明；
2. CloudDrive2 WebDAV 和 115 / Google Drive 最终入库行为必须在真实 VPS 上确认；
3. 流式模式必须用真实的大文件完成一次 Telegram → VPS → CloudDrive2 → 网盘验收。

## 二、最终处理规则

默认环境：

- VPS：最小配置 1 核 CPU、1GB 内存、20GB 硬盘（默认且推荐）；宽裕配置为建议内存至少 2GB、
  硬盘约 50GB；
- 普通落盘任务预算：最小配置 2GB，宽裕配置 20GB；
- 磁盘最少保留：最小配置 6GB，宽裕配置 20GB；
- 内存放行阈值不随这两项推荐配置改变，固定为 1024MB / 512MB；
- 不设置人工固定的下载或上传任务数；
- 并发由 CPU、内存、磁盘、网络、错误率和目的端健康状态动态调节。

文件按以下规则自动分流：

| 文件情况 | 处理方式 | 是否占用完整本地额度 | 失败后的恢复方式 |
|---|---|---:|---|
| 单文件不超过本地预算 | 完整下载到 VPS，再上传 | 是 | 保留完整本地文件并重试上传 |
| 单文件超过本地预算 | Telegram → rclone → CloudDrive2 流式传输 | 否 | 清理临时远端文件，从头重试 |

流式模式通过 `rclone rcat --size` 提供准确文件大小，并使用异步标准输入背压，避免把整个
文件放入内存。远端仍使用临时名称，传输完成后检查大小，再改成正式文件名。

## 三、必须保持的不变量

1. 普通落盘任务按完整文件大小原子预留，合计不超过本地任务预算；
2. 单个文件超过预算时自动流式处理，不要求用户重新部署或调大预算；
3. 磁盘到达安全线时不继续开启传输，CloudDrive2 缓存也受真实剩余空间保护；
4. CPU 或内存持续高压时收缩动态窗口，不继续无上限放行；
5. 用户一次转发即可，未开始任务自动留在队列，不需要重新转发；
6. 远端文件通过大小校验并安全改名后才标记 Bot 传输完成；
7. 普通模式在远端确认前不删除 VPS 完整副本；
8. `/cancel` 只有在本任务远端文件清理成功后才删除本地副本并标记取消；
9. 重启发生在下载、上传、流式传输、远端改名或本地清理阶段时，任务可恢复或重新排队；
10. 文件进入 WebDAV 根目录或所填相对子目录，不建立年份和月份文件夹；
11. 同名文件不覆盖，自动追加任务编号；
12. Bot 只允许配置的 Telegram 数字 ID 使用；
13. “Bot 传输完成”和“网盘官方端已确认”始终分开表达；
14. 115 与 Google Drive 共用同一个 `cd2:` WebDAV remote，不存在 Google 专用 remote。

## 七、仍然存在的边界

### 1. CloudDrive2 特权容器

CloudDrive2 为 FUSE 挂载使用 `privileged: true` 和宿主机 PID 命名空间。这是高权限边界，
两条路线都一样，建议 VPS 只运行本项目，不与钱包、数据库或其他重要服务共用。

### 2. CloudDrive2 缓存不受本地任务预算直接控制

本地任务预算（最小配置 2GB、宽裕配置 20GB）约束的是 Bot 普通落盘任务。流式模式不创建完整
VPS 文件，但 CloudDrive2 仍可能为网盘后台上传使用自己的缓存，这部分不计入 2GB。系统根据
整个分区的真实剩余空间停止新传输，但无法证明闭源缓存永远保持在固定大小。

### 3. 流式模式不能断点续传

流式数据没有完整保存在 VPS。单次 rclone 流式上传不能从任意中点恢复；网络中断后程序会
清理临时远端文件并从 Telegram 开头重试。这是节省磁盘与失败恢复成本之间的明确取舍。

### 4. 远端仅校验大小

普通 WebDAV 对该目的端没有稳定内容哈希。程序校验本地大小、临时远端大小和正式远端大小，
能发现截断和常见写入失败，但不能数学证明同大小内容绝对没有位翻转。

### 5. 网盘最终状态需要人工确认

Bot 能证明 CloudDrive2 WebDAV 已接收并通过大小校验，不能调用可信的 115 或 Google 官方
接口判断最终入库。用户在对应官方客户端看到文件完整且可以播放后，使用 `/confirm <编号>` 记录。

### 6. Windows EXE 未进行商业代码签名

发布包提供 SHA-256，但没有商业 Authenticode 证书，Windows SmartScreen 或安全软件可能
提示未知发布者。

## 八、真实 VPS 最终验收

1. 使用本地开发版部署器重新部署，确认 `TG115_RESULT=SUCCESS`；
2. 确认 CloudDrive2 登录、网盘挂载和原任务数据库仍在；
3. 执行 WebDAV 验收，确认 `TG115_DESTINATION=OK`；
4. 转发一个普通小文件，确认普通落盘流程完成；
5. 转发一个超过所设本地预算的测试文件，确认状态显示流式模式；
6. 传输期间检查 VPS 下载目录，确认没有该大文件的完整副本；
7. 确认远端临时名称最终变成正常文件名；
8. 在 115 或 Google Drive 官方客户端确认大小和播放；
9. 测试一个传输中取消任务，确认本地和本任务远端临时文件都不存在；
10. 重启 VPS，确认队列和已完成任务状态恢复。

只有以上真实链路全部通过，才能称为当前 VPS 上的端到端生产验收完成。

### 2. 部署脚本的实际行为

- 读取 `DESTINATION_TYPE` 时不 `source` 未校验的配置，只按 `KEY=VALUE` 解析；
- 两条路线都要求 `CD2_WEBDAV_URL_B64`、`CD2_WEBDAV_USERNAME_B64`、`CD2_WEBDAV_PASSWORD_B64`，
  都不读取 Google token / client ID / secret；
- 是否安装 `fuse3`/`kmod`、是否检查 `/dev/fuse`、是否创建 `/opt/tg115/clouddrive`、是否
  拉取或启动 CloudDrive2、是否执行网络修复脚本，只由 `DEPLOY_CLOUDDRIVE2` 决定；
- 两条路线都可以打开 CloudDrive2 管理页、修复 CD2 网络并执行 WebDAV 验收；
- 两种模式都不会停止或删除 VPS 上已有的 CloudDrive2 容器和数据。
