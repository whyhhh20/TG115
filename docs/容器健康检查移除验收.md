# Bot 容器健康门槛移除

## 问题与根因

此前只改了 VPS 推荐配置与内存阈值，未移除真正的容器健康检查：

- `remote_install.sh` 等待 Docker `.State.Health.Status=healthy`，否则安装失败。
- 部署器把所有远程安装失败统一显示为“没有通过容器健康检查”，掩盖了实际安装错误。
- WebDAV 验收再次要求输出 `BOT_HEALTH=healthy`。
- Compose 仍定时执行基于心跳文件的健康探针；网络修复后也会等待 `healthy`。

## 当前行为

- Compose 显式设置 `healthcheck.disable: true`。
- 安装只读取容器 `.State.Status` 确认已启动，不读取健康状态，不等待心跳。
- WebDAV 验收保留测试文件写入、大小校验、改名和清理，不再检查容器健康。
- 网络修复恢复凭据后只等待容器运行，不等待健康探针。
- 远程安装失败显示“远程安装失败，请查看上方安装日志”。容器未启动仍正常报错。
- VPS 两项推荐及其预算、保留空间保持当前设置。

## 升级已有 VPS

关闭旧部署器，打开 `dist/TG115-Deployer.exe` 后重新执行一键部署。仅重开程序不会更新 VPS 的 Compose 配置或移除旧容器探针。Compose 会应用新配置；未在本机连接或修改真实 VPS。
